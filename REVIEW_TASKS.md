# Предложенные задачи по улучшению кодовой базы

## 1) Задача на исправление опечатки / неконсистентного нейминга
**Проблема:** в проекте используются разные варианты названия продукта: `csdeaf` (конфиг) и `FaceitDeaf` (текст на главной). Для пользователя это выглядит как опечатка/разнобой брендинга.

**Где видно:**
- `src/config/site.ts` → `name: "csdeaf"`
- `src/app/page.tsx` → "FaceitDeaf is a platform..."

**Задача:** унифицировать отображаемое имя проекта во всех пользовательских точках (`siteConfig.name`, заголовок страницы, навигация, мета-описания).

**Критерий готовности:** во всём UI и SEO-метаданных используется один и тот же вариант названия.

---

## 2) Задача на исправление ошибки (active state в навигации)
**Проблема:** в `main-nav` активность пункта определяется через `pathname.startsWith(item.href)`. Для `Home` (`href: "/"`) выражение истинно на любом маршруте, поэтому `Home` подсвечивается всегда.

**Где видно:**
- `src/components/main-nav.tsx`

**Задача:** изменить логику active state:
- для `"/"` использовать строгое сравнение `pathname === "/"`;
- для остальных пунктов оставить `startsWith` (или более строгую сегментную проверку).

**Критерий готовности:**
- на `/` активен только `Home`;
- на `/ranking` активен только `Ranking`.

---

## 3) Задача на исправление комментария к коду / несоответствия документации
**Проблема:** комментарий в `getPlayerByUsername` говорит, что часть полей будет `null`, но фактически `avatar`, `steam_id_64`, `faceit_elo` заполняются `""` и `0`.

**Где видно:**
- `src/lib/supabase/players.ts` (блок комментария перед `return` и фактические значения в объекте)

**Задача:** привести комментарий и реализацию к одному контракту:
- либо исправить комментарий на фактическое поведение;
- либо вернуть действительно `null`, если это ожидаемая семантика для "данных нет".

**Критерий готовности:** комментарий соответствует коду и не вводит в заблуждение при дальнейшей разработке.

---

## 4) Задача на улучшение теста
**Проблема:** нет теста на логику определения активного пункта меню, из-за чего дефект с `startsWith("/")` не ловится.

**Задача:** добавить unit/component тест для `MainNav`:
- проверка, что на маршруте `/` активен только `Home`;
- проверка, что на `/ranking` активен только `Ranking`;
- (опционально) проверка для вложенных маршрутов `/ranking/...`.

**Критерий готовности:** тест падает на текущей реализации и проходит после фикса.
